# 测试与运行方案

> 本文回答三个问题：**测试是什么**、**为什么要这样运行**、**完整的运行方案**。
> 对应代码版本：PR #1 修复后的 `codex/project-appraisal` 分支。

---

## 一、测试是什么

本项目的测试是**针对确定性财务引擎和关键数据链路的自动化验证**，全部用 [Vitest](https://vitest.dev/) 编写，位于 `tests/` 目录。当前共 7 个测试文件、36 项测试：

| 测试文件 | 验证对象 | 验证内容 |
| --- | --- | --- |
| `finance.test.ts` | `lib/finance/math.ts` 纯数学函数 | NPV、XNPV、IRR、XIRR、MIRR、回收期、利润指数、盈亏平衡的数值正确性；非法折现率、不可能盈亏平衡的报错 |
| `appraisal.test.ts` | `lib/finance/appraisal.ts` 评估引擎 | 增量现金流不含沉没成本；已确认隐藏成本计入首期投入；名义/实际口径不一致时阻止计算；反向估值与手算一致（100 万三年期 → 上限 751,314.8）；安全边际为负判定不可行；决策审计记录包含假设、失败条件和下一步；盈亏平衡来自经营驱动；手工现金流覆盖经营驱动并清空逐期收入；XNPV/XIRR 与独立结果一致；收入临界值超过 200% 时的降级提示 |
| `validate.test.ts` | `lib/finance/validate.ts` 输入校验层 | 残缺 JSON 自动补默认值而非崩溃；非法类型抛出中文错误；周期取整且下限为 1；非法枚举回退安全默认；手工/带日期现金流格式校验与互斥 |
| `repository.test.ts` | `lib/db/repository.ts` SQLite 持久层 | 保存、列表、按 id 读取；同 id 保存是更新而非新增；删除存在与不存在的项目 |
| `market.test.ts` | `lib/market/providers.ts` 市场数据 | 汇率、FRED、Trading Economics 的快照字段（来源、观察时间、是否过期）；接口失败与 Key 缺失的处理 |
| `report.test.ts` | `lib/report/export.ts` 导出 | 决策审计 Markdown 结构；现金流 CSV 往返；项目 JSON 导出/导入 |
| `project-app.test.tsx` | `components/project-app.tsx` 前端 | 六阶段向导首屏渲染；进入工作台后修改收益驱动，NPV 实时重算；反向估值面板可见 |

### 测试的设计意图

1. **财务结果必须与独立手算一致。** 例如"三年后收到 100 万、折现率 10%、价值上限 751,314.8 元"这类用例的答案是人算出来的，测试把它固化成回归基准——以后任何人改公式，数值一旦偏离立刻失败。
2. **边界条件比正常路径更重要。** 多次变号的现金流（IRR 多解）、零收益、负收益、口径不一致、残缺 JSON、非法日期——真实用户一定会撞到这些，测试确保系统给出明确警告或中文错误，而不是静默算错或直接崩溃。
3. **前端只测"关键交互链路"**，不测样式。组件测试验证"改参数 → NPV 重算"这条核心价值链路，动画（GSAP）和图表（Recharts）在测试中被打桩跳过，因为动效正确性无法、也不需要用断言表达。

## 二、为什么要这样运行

### 为什么是 Vitest 而不是 Jest

项目是纯 ESM（`"type": "module"`）+ Next.js 16 + React 19。Vitest 原生支持 ESM 和 TypeScript，无需额外的转译配置（`vitest.config.ts` 只有十几行），与 Vite 生态的模块解析行为一致，启动和运行都比 Jest 快一个量级。

### 为什么测试分层：纯函数 → 持久层 → 组件

- **财务引擎（math / appraisal / validate）是无副作用纯函数**，不依赖浏览器、网络或数据库，可以直接断言精确数值。这是刻意为之的架构：财务逻辑与 React UI 分离，保证"数学可以被独立审计"。
- **持久层测试用 `:memory:` SQLite**，每个用例一个独立内存库，测试之间互不污染，也不需要清理临时文件。
- **组件测试用 jsdom**（轻量 DOM 模拟），不打真浏览器，速度快且能在任何机器上运行；GSAP 被 mock 掉，因为 jsdom 不执行真实动画。

### 为什么测试不访问网络

所有市场数据测试都不打真实 API。原因有三个：测试必须**确定性**（网络抖动不应让测试随机失败）；必须**离线可跑**（CI 和本地都可能没网）；必须**不消耗外部 API 配额**（FRED / Trading Economics 有 Key 限制）。外部接口的正确性由"快照字段是否完整、失败时是否报错而不是静默计算"这类行为断言来保证。

### 为什么验证流程是四道命令

```bash
npm test           # 1. 行为正确性：数值、边界、交互
npm run typecheck  # 2. 类型正确性：tsc 严格模式，防"运行时才炸"
npm run lint       # 3. 代码规范：ESLint + Next.js 规则，防坏味道积累
npm run build      # 4. 生产构建：验证服务端/客户端边界、静态生成、打包
```

四者检查的是**不同维度**：测试再全也抓不到类型错误（测试只跑写到的路径），类型检查再严也抓不到数值错误（类型不知道 751,314.8 才是对的）。只有构建通过才能证明服务端组件与客户端组件的边界没有违规。四道全绿才视为一次有效变更。

## 三、完整运行方案

### 3.1 环境要求

- Node.js **20 或更高版本**（推荐 22 LTS）
- npm 10+
- 无需任何 API Key 即可运行核心功能（FRED / Trading Economics 为可选增强）

### 3.2 获取与安装

```bash
git clone https://github.com/SamuelCine/project-appraisal.git
cd project-appraisal

# PR #1 合并前，切换到完整功能分支
git switch codex/project-appraisal

npm install
```

**中国大陆网络提示**：如果 `npm install` 报 `ECONNRESET` / 超时，是 npm 官方源（registry.npmjs.org）连不上，改用镜像源：

```bash
npm install --registry=https://registry.npmmirror.com
```

`better-sqlite3` 是原生模块，安装时会自动下载预编译二进制；如遇编译问题，同样需要镜像源（它会从镜像下载 prebuilt）。

### 3.3 日常使用

**方式一：命令行**

```bash
# 开发模式（修改代码即时生效）
npm run dev
# 浏览器打开 http://localhost:3000

# 生产模式（先构建再启动，性能更好）
npm run build
npm start
```

**方式二：桌面端一键启动（推荐日常使用）**

双击项目根目录的 `启动衡策.bat`：自动安装依赖（首次）、自动构建（首次）、启动服务并打开浏览器；关闭黑色命令行窗口即停止服务。若服务已在运行，脚本只会打开浏览器，不会重复启动。

**方式三：安装为桌面应用（独立窗口 + 任务栏图标）**

先用方式一或二启动服务，然后在浏览器打开 `http://localhost:3000`：

- Edge：菜单 → **应用 → 将此站点安装为应用**
- Chrome：菜单 → **保存并分享 → 安装页面**

安装后"衡策"有独立窗口和自己的图标，看起来与桌面软件无异；项目已内置 `manifest.webmanifest`，名称、主题色和图标均已配置。注意：这只是窗口壳，数据和服务仍在本地，每次使用前需保证服务已启动（双击 `启动衡策.bat` 即可）。

**一次完整的使用流程**：

1. 首页是六阶段考察向导，逐阶段填写或确认：决策定义 → 商业证据 → 隐藏成本 → 收益驱动 → 财务参数 → 风险小结。
2. 点"进入决策工作台"，三栏布局实时联动：
   - **左栏**：假设可信度、隐藏成本勾选、风险提示；
   - **中栏**：收益/成本参数（改动即时重算）、累计现金流与逐期收入图表、手工现金流 CSV、反向投资边界（最低可行投入 / 价值上限 / 谈判下限 / 安全边际）；
   - **右栏**：NPV / IRR / MIRR / 利润指数 / 回收期 / 盈亏平衡（有带日期现金流时追加 XNPV / XIRR）、三情景、敏感性与临界值、决策建议、可折叠的决策审计记录。
3. 顶栏操作：**保存项目**（首次创建、之后原地更新）、**打开项目**（列表、载入、删除、新建空白）、**导入 / 导出 JSON**、**导出 Markdown 决策审计报告**、**假设依据**抽屉（USD/CNY 参考汇率）。
4. 手工现金流 CSV 格式（表头必填，覆盖经营驱动）：

```csv
period,amount
0,-100000
1,40000
2,50000
```

   带日期现金流（启用 XNPV/XIRR，与手工现金流互斥）：

```csv
date,amount
2026-01-01,-100000
2027-06-01,80000
2028-12-31,120000
```

### 3.4 验证一次变更的标准流程

```bash
npm test && npm run typecheck && npm run lint && npm run build
```

预期结果：7 个测试文件、36 项测试通过；typecheck 与 lint 无输出；build 列出 9 条路由后成功退出。任何一步失败都应先修复再提交。

### 3.5 可选环境变量

```bash
# .env.local（不要提交到 Git）
FRED_API_KEY=你的_FRED_Key                    # 启用美国利率/通胀宏观数据
TRADING_ECONOMICS_API_KEY=你的_TE_Key         # 启用全球宏观与商品数据
PROJECT_DB_PATH=/绝对路径/project-appraisal.db  # 自定义数据库位置
```

未配置 Key 时，`/api/market?type=fred` 返回 503 和明确错误，不影响汇率等免费功能。

### 3.6 API 速查

| 方法与路径 | 用途 | 说明 |
| --- | --- | --- |
| `GET /api/projects` | 项目列表 | |
| `POST /api/projects` | 新建项目 | body 为项目 JSON，缺失字段自动补默认值 |
| `GET /api/projects/:id` | 读取项目 | 不存在返回 404 |
| `PUT /api/projects/:id` | 更新项目 | 原地更新，不产生重复 |
| `DELETE /api/projects/:id` | 删除项目 | |
| `POST /api/projects/:id/evaluate` | 完整财务评估 | 空 body 使用已保存项目；带 body 则评估传入模型 |
| `POST /api/projects/:id/scenarios` | 三情景 | 同上 |
| `POST /api/projects/:id/reverse` | 反向估值 | body 必须含 `futureCashFlows`、`minimumHurdleRate`、`stretchReturnRate` |
| `POST /api/explain` | 生成决策审计记录与 Markdown | body 为项目 JSON |
| `GET /api/market?type=fx&base=USD&quote=CNY` | 参考汇率 | `type=fred` / `type=te` 需对应 Key |

所有接口的错误都是 JSON：`{ "error": "中文错误信息" }`，HTTP 状态码语义化（400 输入问题 / 404 不存在 / 503 外部数据不可用）。

### 3.7 数据与隐私

- 项目数据保存在本地 SQLite（默认 `项目目录/project-appraisal.db`），已在 `.gitignore` 中排除。
- 无账号系统、无遥测上报；除用户主动点击"假设依据"获取汇率外，不发起任何外部请求。
- 数据库文件、`.env`、导出的报告都不应提交到 Git。

### 3.8 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `npm install` 报 ECONNRESET | 官方 npm 源不可达 | 加 `--registry=https://registry.npmmirror.com` |
| 端口 3000 被占用 | 上次的 dev/start 进程没退出 | 结束占用进程，或 `npm run dev -- -p 3001` |
| FRED/TE 接口 503 | 未配置 API Key | 配置 `.env.local` 后重启；或忽略，不影响核心功能 |
| 想重置全部数据 | — | 停止服务后删除 `project-appraisal.db` 文件即可 |
| `npm test` 在 Windows 中文系统显示乱码 | 控制台编码 | 不影响结果；可用 `chcp 65001` 切 UTF-8 |
