# 衡策：项目考察与反向投资决策系统

衡策是一套本地优先的项目资本预算工具，用金融和商业验证框架帮助普通用户回答：项目实际需要投入多少、未来可能产生多少现金流、今天最多值得投入多少，以及哪些隐藏成本或错误假设可能使项目失败。

它不是股票行情终端。外部市场数据只用于汇率、通胀、折现率和成本假设。

## 核心能力

- 六阶段引导式项目考察：决策定义、商业验证、隐藏成本、收益驱动、财务计算、风险决策。
- NPV、XNPV、IRR、XIRR、MIRR、ROI、利润指数、回收期、折现回收期和盈亏平衡计算。
- 悲观、基准、乐观三情景，单因素敏感性和 NPV 临界值。
- 反向计算最低可行投入、谈判报价区间、投资价值上限与安全边际。
- 可审计决策记录：展示输入、公式、中间结果、来源、失败条件和下一步验证任务。
- SQLite 本地保存，JSON、CSV、Markdown 导出。
- Frankfurter/ECB 免费参考汇率，FRED 与 Trading Economics 可选接入。
- 不使用 OpenAI API Key；AI 不参与数学计算。

## 如何使用

### 1. 定义决策

填写项目目标、周期、币种、行业和你的角色。必须同时记录“不做项目”的基准方案，并尽量建立一个可比较的替代方案。

### 2. 验证商业逻辑

记录客户、需求证据、市场容量、竞争者、替代品、价格接受度和进入壁垒。将输入标记为“已知、估算、待验证”；没有证据时建立验证任务，不自动编造数字。

### 3. 补全隐藏成本

检查设备、装修、研发、许可、押金、库存、招聘、营销、创始人时间、获客、渠道、维护、税费、营运资金、延期、返工、汇率、机会成本和退出成本。沉没成本单列，但不进入继续投资决策。

### 4. 建立收益驱动

默认使用：

```text
收入 = 客户数 × 转化率 × 客单价 × 购买频次
自由现金流 = 收入 − 现金运营成本 − 税费 − 资本开支 − 营运资金增加 + 税后残值
```

不要只填写一个“希望达到的总收入”；每个关键假设应有来源、适用日期和可信度。

### 5. 设置财务门槛

填写最低可接受回报率和目标回报率。实际现金流搭配实际折现率，名义现金流搭配名义折现率。项目整体现金流中不要再次扣除贷款利息，避免与资金成本重复计算。

### 6. 阅读结果与风险

- NPV 是主要价值判断指标。
- IRR 用于比较回报门槛；现金流多次变号时以 NPV/MIRR 为主。
- 三情景用于观察合理范围，不代表概率承诺。
- 临界值说明价格、销量、成本或延期达到什么程度会让 NPV 归零。
- 最终建议由确定性规则产生，解释层不能修改数学结果。

## 反向投资示例

假设三年后项目只产生 100 万元净现金流：

```text
投资价值上限 = 1,000,000 / (1 + 最低可接受回报率)^3
谈判下限 = 1,000,000 / (1 + 更高目标回报率)^3
安全边际 = 投资价值上限 − 最低可行投入
```

若最低回报要求为 10%、目标回报率为 20%、最低可行投入为 60 万元：

- 投资价值上限约 75.13 万元。
- 谈判下限约 57.87 万元。
- 安全边际约 15.13 万元。

这只能说明未来现金流的今日价值，不能证明“三年后获得 100 万元”这一假设一定成立。

## 市场数据配置

免费参考汇率不需要 Key。可选数据源通过运行环境设置：

```bash
FRED_API_KEY=你的_FRED_Key
TRADING_ECONOMICS_API_KEY=你的_TE_Key
PROJECT_DB_PATH=/绝对路径/project-appraisal.db
```

不要把真实 Key 提交到 Git 或写入 Obsidian。参考汇率不是交易报价；接口失败、数据过期或单位不一致时应手工复核并记录覆盖原因。

## 数据与隐私

- 默认数据库：项目目录下的 `project-appraisal.db`。
- 可用 `PROJECT_DB_PATH` 改变数据库位置。
- 应用在本地运行，没有账号系统。
- 项目数据不会因为进入公开 GitHub 仓库而自动上传；请勿提交本地数据库或 `.env` 文件。
